# US-19 — Back up chat history to Google Drive

**As a user**, I want my chat history database automatically backed up to Google Drive so that my conversations are not lost if my local disk fails.

## Background

Depends on US-16 (Drive client and folder infrastructure). The Pebble database is always open and cannot be copied directly. This story uses `pebble.DB.Checkpoint()` to create a consistent, point-in-time snapshot of the entire database while it remains live, then uploads it as a single compressed archive. Only one backup file is kept in Drive at a time (overwritten on each run).

This feature is separately opt-in via `drive_sync.pebble_backup.enabled` and can be enabled independently of vault sync (though it shares the Drive client and folder).

## Acceptance Criteria

- When `drive_sync.enabled: true` and `drive_sync.pebble_backup.enabled: true`, a background goroutine creates a Pebble checkpoint every `drive_sync.pebble_backup.interval_mins` minutes (default 30).
- The checkpoint is archived as a `tar.gz` and uploaded to Drive as `autowiki-pebble-backup.tar.gz` inside the vault folder, overwriting the previous backup. The Drive file ID for the backup is stored in Pebble under `drive_sync:pebble_backup_file_id` to enable update-in-place.
- On graceful shutdown (SIGINT/SIGTERM), one final backup runs before the process exits. It times out after 60 seconds to avoid hanging shutdown.
- `drive_sync:last_pebble_backup` is updated in Pebble after each successful upload (visible via `GET /api/drive/status` from US-18).
- Backup errors are logged but do not crash the server or affect chat.

## Implementation Checklist

### Group 1 — Drive API: update-in-place

- [ ] Add `UploadFile(fileID, localPath, mimeType string) error` to `DriveClient` — updates an existing Drive file by ID (used to overwrite the backup in-place without creating a new file each time). Distinct from the existing `Upload` which creates-or-updates by path.
- [ ] Tests: UploadFile calls the correct Drive API update endpoint.

### Group 2 — Backup manager (`internal/sync/backup.go`)

- [ ] Implement `BackupManager` holding `*pebble.DB`, `DriveClient`, `State`, Pebble path, and config.
- [ ] `Backup(ctx context.Context) error`:
  1. Create a temp directory and call `db.Checkpoint(tmpDir)`.
  2. Archive the checkpoint directory as a `tar.gz` into a second temp file.
  3. Look up `drive_sync:pebble_backup_file_id` from Pebble state.
     - If present, call `UploadFile` to overwrite the existing Drive file.
     - If absent, call `Upload` to create the file; store the returned file ID in `drive_sync:pebble_backup_file_id`.
  4. Remove the temp checkpoint dir and archive.
  5. Update `drive_sync:last_pebble_backup` in state.
- [ ] `Start(ctx context.Context)` loops: wait `interval_mins`, call `Backup`. On context cancellation, call `Backup` once with a 60 s deadline before returning.
- [ ] Tests:
  - `Backup` produces a valid `tar.gz` from a real Pebble checkpoint.
  - The archive is a valid tar.gz (can be extracted and files match the checkpoint).
  - First backup creates a Drive file and stores its ID in state; subsequent backup calls `UploadFile` with that ID.
  - `last_pebble_backup` is updated after a successful backup.

### Group 3 — Wire into server

- [ ] In `cmd/server/main.go`, when both `drive_sync.enabled` and `drive_sync.pebble_backup.enabled` are true, start `BackupManager` as a background goroutine alongside `SyncManager`.
- [ ] Register a shutdown hook that cancels the `BackupManager` context (triggering the final backup) and waits for it to finish before the process exits.
