# US-04 — Store text knowledge in vault

**As a user**, I can share something I've learned in a chat message so that the LLM stores the relevant information in my Obsidian vault without me having to organise it manually.

## Acceptance Criteria

- After sending a knowledge-bearing message, the relevant vault pages are created or updated.
- A "Saved to vault" summary is displayed inline after the assistant's reply, listing which pages were changed.
- If the message contains no new knowledge (e.g., a greeting or a question), no vault writes occur and no summary is shown.

## Design: Tool Use Pattern

The assistant reply streams to the user in real time (same as US-03). Vault writes are driven by a `save_to_vault` tool declared in the Anthropic API request. After the stream ends, if the model decided to call the tool the handler executes the writes and emits a `vault` SSE event. This is one API call, no parsing of embedded JSON, and matches how production AI assistants (ChatGPT memory, Claude.ai Projects) handle structured side-effects alongside streaming replies.

## Implementation Checklist

### Vault Manager (`internal/vault`)
- [x] Define `Manager` struct backed by `VAULT_PATH`
- [x] `ReadFile(path string) (string, error)` — read a vault-relative `.md` file; return empty string if not found
- [x] `WriteFile(path, content string) error` — write (create or overwrite) a vault-relative `.md` file, creating parent dirs as needed
- [x] `AppendLog(entry string) error` — append a timestamped entry to `log.md`
- [x] `ReadIndex() (string, error)` — convenience wrapper for `index.md`
- [x] Unit tests with a temp directory as the vault root

### LLM Client — tool use (`internal/llm`)
- [x] Declare a `save_to_vault` tool with JSON schema `{ pages: [{ path: string, content: string }] }`
- [x] Include the tool in every `POST /v1/messages` request with `tool_choice: auto`
- [x] `Stream(ctx, messages, indexMD string)` — `indexMD` appended to system prompt under `## Vault Index` when non-empty; tool_use block parsing done by chat handler consuming the raw SSE body
- [x] System prompt includes `index.md` content so the model knows the existing vault structure when deciding what to write
- [x] Unit tests: tool definition present in request, `tool_choice: auto`, indexMD in system prompt

### Chat Handler — vault integration (`internal/chat`)
- [x] Accept a `vault.Manager` dependency in `Handler`
- [x] Parse Anthropic SSE: detect `content_block_start` (tool_use type), accumulate `input_json_delta` fragments
- [x] After stream ends: call `vault.Manager.WriteFile` for each page, then `vault.Manager.AppendLog`
- [x] Emit SSE `vault` event listing changed paths: `data: {"changes":[{"path":"..."}]}` (omitted if no writes)
- [x] Handler tests: vault-write path, no-write path

### Frontend — vault summary
- [x] On `vault` SSE event: render a collapsible "Saved to vault" section beneath the assistant reply listing each changed path

### Vault index maintenance
- [x] After vault writes, update `index.md` to reflect new/changed pages — LLM instruction added to system prompt so `save_to_vault` calls include an updated `index.md` page
- [x] System prompt test: verify the prompt instructs the LLM to keep `index.md` current
