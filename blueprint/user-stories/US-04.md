# US-04 — Store text knowledge in vault

**As a user**, I can share something I've learned in a chat message so that the LLM stores the relevant information in my Obsidian vault without me having to organise it manually.

## Acceptance Criteria

- After sending a knowledge-bearing message, the relevant vault pages are created or updated.
- A "Saved to vault" summary is displayed inline after the assistant's reply, listing which pages were changed.
- If the message contains no new knowledge (e.g., a greeting or a question), no vault writes occur and no summary is shown.

## Implementation Checklist

### Vault Manager (`internal/vault`)
- [ ] Define `Manager` struct backed by `VAULT_PATH`
- [ ] `ReadFile(path string) (string, error)` — read a vault-relative `.md` file; return empty string if not found
- [ ] `WriteFile(path, content string) error` — write (create or overwrite) a vault-relative `.md` file, creating parent dirs as needed
- [ ] `AppendLog(entry string) error` — append a timestamped entry to `log.md`
- [ ] `ReadIndex() (string, error)` — convenience wrapper for `index.md`
- [ ] Unit tests with a temp directory as the vault root

### LLM Ingest Pipeline (`internal/llm`)
- [ ] Define `IngestRequest`: `{ UserMessage, ConversationHistory []Message, IndexMD string }`
- [ ] Define `IngestResponse`: `{ Reply string, VaultWrites []VaultWrite }` where `VaultWrite = { Path, Content string }`
- [ ] `Ingest(ctx, req IngestRequest) (stream, error)` — streams the reply; vault writes arrive as a final structured SSE event once the LLM finishes
- [ ] Prompt design: system prompt includes `schema.md` content and `index.md`; instructs the LLM to reply conversationally AND emit a JSON block of vault writes (empty array if nothing to store); LLM judges whether the message warrants a write
- [ ] Unit tests with stubbed HTTP transport

### Chat Handler — vault integration (`internal/chat`)
- [ ] Switch `POST /api/chat` from `llm.Stream` to `llm.Ingest`
- [ ] After stream ends: call `vault.Manager.WriteFile` for each write, then `AppendLog`
- [ ] Emit SSE `vault` event listing changed paths: `data: {"changes":[{"path":"..."}]}`  (omitted if no writes)
- [ ] Update handler tests to cover vault write and no-write paths

### Frontend — vault summary
- [ ] On `vault` SSE event: render a collapsible "Saved to vault" section beneath the assistant reply listing each changed path
