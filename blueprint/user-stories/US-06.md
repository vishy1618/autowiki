# US-06 — Share a document

**As a user**, I can attach a PDF to a chat message so that its content is extracted and indexed in my vault.

## Acceptance Criteria

- The raw file is saved to `_attachments/` (already handled by the US-05 attachment pipeline).
- For PDFs ≤ 5 MB, the LLM produces a description/summary which is stored in the `.meta.json` sidecar and injected into the conversation context.
- For PDFs > 5 MB, the upload still succeeds and the file is saved, but the sidecar description is left empty and the context injection notes the file is too large to process.
- The vault pages written by the LLM reference the saved attachment via Obsidian embed syntax: `![[_attachments/...]]`.
- Non-PDF file types are unaffected.

## Design Notes

### Why PDFs only (v1)
Anthropic's API has a native `document` content block that accepts base64-encoded PDFs directly — no Go parsing library needed. Other document types (`.docx`, `.txt`) can be added later if needed.

### Size limit
5 MB covers the vast majority of readable PDFs. Large scanned PDFs degrade Claude's extraction quality and risk hitting API limits. 5 MB is checked against the raw file bytes before encoding.

### Data flow
1. `POST /api/attachments` receives the PDF.
2. If `mediaType == "application/pdf"` and `len(data) <= 5_000_000`: call `DescribeDocument` on the `Describer` interface.
3. `DescribeDocument` sends a single Anthropic messages request with a `document` content block (base64 PDF) and a text prompt asking for a concise summary. Returns the summary string.
4. Summary stored in `.meta.json` sidecar as `description`.
5. Chat handler injects `[Attached: filename (vault path: ...) — summary]` into the user message — identical to the image path.
