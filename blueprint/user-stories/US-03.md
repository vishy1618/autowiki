# US-03 — Share text knowledge

**As a user**, I can type a message describing something I've learned or read so that the relevant information is stored in my vault without me having to decide how to organize it.

## Acceptance Criteria

- After sending the message, the assistant responds and any new or updated vault pages are summarized inline.
- If the message contains no new knowledge (e.g., a greeting), no vault writes occur.

## Implementation Checklist

### Chat History Store (`internal/store`)
- [ ] Define `ChatSession` model: `id`, `created_at`, `last_active_at`
- [ ] Define `Message` model: `id`, `session_id`, `role` (user|assistant), `content`, `created_at`
- [ ] Extend `SessionStore` interface (or add a new `ChatStore` interface) with:
  - `ResolveSession() (ChatSession, error)` — returns the active session, creating a new one if none exists or the last was >30 min ago
  - `AppendMessage(msg Message) error`
  - `GetSession(id string) (ChatSession, error)`
  - `ListMessages(sessionID string) ([]Message, error)`
- [ ] Implement against Pebble using the key schema from TRD §4.6
- [ ] Unit tests via shared suite (MemStore + PebbleStore)

### Vault Manager (`internal/vault`)
- [ ] Define `Manager` struct backed by `VAULT_PATH`
- [ ] `ReadFile(path string) (string, error)` — read a vault-relative `.md` file; return empty string if not found
- [ ] `WriteFile(path, content string) error` — write (create or overwrite) a vault-relative `.md` file, creating parent dirs as needed
- [ ] `AppendLog(entry string) error` — append a timestamped entry to `log.md`
- [ ] `ReadIndex() (string, error)` — convenience wrapper for reading `index.md`
- [ ] Unit tests with a temp directory as the vault root

### LLM Client (`internal/llm`)
- [ ] Define `Client` struct wrapping the Anthropic API (`anthropic-ai/sdk` or raw HTTP)
- [ ] Define `IngestRequest`: `{ UserMessage, IndexMD string }`
- [ ] Define `IngestResponse`: `{ Reply string, VaultWrites []VaultWrite }` where `VaultWrite = { Path, Content string }`
- [ ] Implement `Ingest(ctx, req) (stream, error)` — streams the reply via SSE deltas; vault writes arrive in a final structured event
- [ ] Prompt design: system prompt includes vault `schema.md` + `index.md`; instructs LLM to reply conversationally AND produce a JSON block of vault writes (or none); LLM judges whether the message warrants a write
- [ ] Unit tests with a stubbed HTTP transport

### Chat Handler (`internal/chat`)
- [ ] Define `Handler` struct wiring together `ChatStore`, `vault.Manager`, `llm.Client`
- [ ] Register `POST /api/chat` (protected by auth middleware), accepts `application/x-www-form-urlencoded` or `multipart/form-data` with field `message`
- [ ] Resolve or create the active chat session via `ChatStore`
- [ ] Persist the user message
- [ ] Call `llm.Client.Ingest`, stream response tokens back to client as SSE `delta` events
- [ ] After stream ends: apply `VaultWrites` (call `vault.Manager.WriteFile` for each), append to `log.md`
- [ ] Persist the assistant message
- [ ] Emit a final SSE `vault` event listing changed paths (empty array if no writes)
- [ ] Emit SSE `done` event
- [ ] Handler tests using stubbed LLM and in-memory store

### Frontend — Chat UI (`web/`)
- [ ] Replace home route placeholder with a chat layout: message thread + input bar
- [ ] Input bar: textarea + send button; submit on Enter (Shift+Enter for newline)
- [ ] On send: `POST /api/chat` via `fetch`, consume the SSE response stream
- [ ] Render `delta` events as streaming text on the assistant bubble in real time
- [ ] On `vault` event: render a collapsible "Saved to vault" summary listing changed paths
- [ ] On `done` event: finalize the assistant message, re-enable input
- [ ] On error: display inline error message, re-enable input
- [ ] Show a spinner/typing indicator while the stream is in flight
