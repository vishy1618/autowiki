# US-03 — Basic streaming chat

**As a user**, I can type a message and receive a streaming reply from an LLM assistant so that I can have a real-time conversation.

## Acceptance Criteria

- The assistant's reply streams into the UI token by token.
- Messages are persisted in the chat history store.
- A new chat session is created automatically; if there has been no activity for 24 hours, subsequent messages start a fresh session.

## Implementation Checklist

### Chat History Store (`internal/store`)
- [x] Define `ChatSession` model: `id`, `created_at`, `last_active_at`
- [x] Define `Message` model: `id`, `session_id`, `role` (user|assistant), `content`, `created_at`
- [x] Add `ChatStore` interface: `ResolveSession() (ChatSession, error)`, `AppendMessage(Message) error`, `ListMessages(sessionID string) ([]Message, error)`
- [x] Implement `ChatStore` against Pebble using the key schema from TRD §4.6
- [x] Unit tests via shared suite (MemChatStore + PebbleChatStore)

### LLM Client (`internal/llm`)
- [x] Define `Client` struct that calls the Anthropic Messages API
- [x] `Stream(ctx, messages []Message) (io.ReadCloser, error)` — opens a streaming request and returns the raw SSE body for the caller to consume
- [x] Unit tests with a stubbed HTTP transport
- [x] System prompt: assistant identifies as autowiki and understands its purpose as a personal knowledge partner

### Chat Handler (`internal/chat`)
- [x] Define `Handler` struct wiring `ChatStore` and `llm.Client`
- [x] Register `POST /api/chat` (protected by auth middleware), field `message` (plain text)
- [x] Resolve or create the active session via `ChatStore.ResolveSession`
- [x] Persist the user message via `ChatStore.AppendMessage`
- [x] Call `llm.Client.Stream`, forward token deltas to the client as SSE `delta` events: `data: {"text":"..."}`
- [x] After stream ends: persist the assembled assistant message
- [x] Emit SSE `done` event: `data: {"session_id":"..."}`
- [x] Handler tests using stubbed LLM and in-memory store

### Frontend — Chat UI
- [x] Replace home route placeholder with a chat layout: scrollable message thread + input bar at the bottom
- [x] Input bar: textarea + send button; submit on Enter (Shift+Enter for newline)
- [x] On send: `POST /api/chat` with `fetch`, open the SSE response stream
- [x] Render `delta` events as streaming text on the in-flight assistant bubble
- [x] On `done`: finalise the assistant bubble, re-enable input
- [x] On error: display an inline error message, re-enable input
- [x] Show a typing indicator while the stream is in flight
- [x] Render assistant messages as Markdown (GFM)
