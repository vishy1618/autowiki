# US-11 — Overnight wiki consolidation

**As a user**, I can leave the server running overnight so that my vault is automatically curated — cross-references improved, orphan pages resolved, structure tidied — without any action on my part.

## Acceptance Criteria

- The dream state runs once per night during a random time in the 1–5 am IST window.
- It reads the vault, produces a consolidation plan via a lightweight topology LLM call, then improves pages in batches (or in one pass for small vaults ≤ 25 pages).
- No knowledge is deleted or overwritten without first being confirmed saved elsewhere.
- A dated summary of changes is appended to `log.md` each night it runs.
- If tonight's entry already exists in `log.md`, the run is skipped (idempotent).

## Implementation Checklist

### Group 1 — Vault: path traversal protection

- [x] Add `safePath(rel string) (string, error)` helper to `vault.Manager`. Joins `rel` with the vault root, calls `filepath.Clean`, then verifies the result is still inside the root. Returns an error for any path that escapes (e.g. `../../etc`).
- [x] Apply `safePath` to all existing vault methods: `ReadFile`, `WriteFile`, `AppendLog`, `ReadIndex`.
- [x] Tests:
  - `safePath` rejects `../outside`, `../../etc/passwd`, and absolute paths pointing outside the vault.
  - `safePath` accepts valid relative paths and paths with redundant `.` or non-escaping `..` segments.
  - Existing methods return an error when called with an escaping path.

### Group 2 — Vault: new filesystem methods

- [x] `ListVault(path string, recursive bool) ([]VaultEntry, error)` — lists files and subdirectories under `path` (default: vault root). Each `VaultEntry` has `Path string`, `Type string` (`"file"` or `"dir"`), `Size int64`. Uses `safePath` on the input path.
- [x] `ReadFilePartial(path string, maxChars int) (string, error)` — reads the first `maxChars` bytes of a file via `io.LimitReader`. Uses `safePath`.
- [x] `MoveFile(from, to string) error` — moves a file within the vault; creates parent directories as needed. Both `from` and `to` validated with `safePath`.
- [x] `DeleteItem(path string, recursive bool) error` — deletes a file or directory. Non-empty directory with `recursive: false` returns an error. Uses `safePath`.
- [x] Tests for each method:
  - `ListVault` lists only files/dirs under the given path; `recursive` walks subtrees.
  - `ListVault` returns an error for escaping paths.
  - `ReadFilePartial` returns at most `maxChars` characters even for large files.
  - `ReadFilePartial` returns an error for escaping paths.
  - `MoveFile` moves the file, creates parent dirs, errors if `from` does not exist.
  - `MoveFile` errors if either path escapes the vault root.
  - `DeleteItem` deletes a file; errors on non-empty dir without `recursive`.
  - `DeleteItem` with `recursive: true` removes a non-empty directory.
  - `DeleteItem` errors if path escapes the vault root.

### Group 4 — Dream: core goroutine and scheduling

- [x] Implement `dream.Runner` with a `Start(ctx context.Context)` method that loops indefinitely until the context is cancelled.
- [x] Each loop iteration computes the next 1–5 am IST fire time (random within the window), sleeps until then, runs the consolidation, then sleeps again.
- [x] Before running, check `log.md` for today's dated entry using `vault.ReadFilePartial` on the last 500 chars. If found, skip and wait for tomorrow.
- [x] Wire `dream.Runner` into `cmd/server/main.go` as a background goroutine.
- [x] Tests:
  - Next fire time is always in the 1–5 am IST window.
  - If today's log entry exists, consolidation is skipped.

### Group 5 — Dream: consolidation logic

- [x] Implement `consolidate(ctx context.Context)`:
  1. Call `vault.ListVault("", true)` to get all files including orphans.
  2. Read the first 500 chars of each `.md` file via `ReadFilePartial`.
  3. If total file count ≤ 25: single LLM call with full page content — skip to step 6.
  4. **Topology call**: send index + first-500-char summaries to LLM; receive a JSON plan grouping pages into batches with tasks (cross-reference, orphan resolution, structure).
  5. **Batch worker calls**: for each batch, send topology JSON + full batch page content; LLM uses tools (`read_page`, `list_vault`, `move_page`, `save_to_vault`, `delete_item`) to execute improvements.
  6. Collect a change log (pages written, moved, deleted) across all calls.
  7. Append a dated `log.md` entry summarising the changes.
- [x] LLM system prompt for dream calls includes:
  - The safety rule (no delete without confirmed move).
  - Instruction to use `[[wikilinks]]` and follow vault schema.
  - Instruction to prefer additive changes; only restructure when clearly beneficial.
- [x] Tests:
  - Small vault (≤ 25 pages) triggers a single LLM call, not a topology + batch flow.
  - Large vault triggers a topology call followed by one call per batch.
  - A dated log entry is appended after consolidation.
  - If the LLM attempts `delete_item` without a prior `save_to_vault` for the same content, the system prompt guidance prevents it (prompt-level; not code-enforced).
