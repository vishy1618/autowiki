# US-18 — Drive sync status

**As a user**, I want to see the current state of my Google Drive sync so that I know whether my vault is connected and up to date.

## Background

Depends on US-16 and US-17. This story adds observability: a `GET /api/drive/status` API endpoint and a minimal status indicator in the UI. No new sync logic is introduced.

## Acceptance Criteria

- `GET /api/drive/status` (auth-guarded) returns:
  ```json
  {
    "enabled": true,
    "connected": true,
    "last_vault_sync": "2026-04-20T10:30:00Z",
    "last_pebble_backup": null,
    "last_error": null
  }
  ```
  - `enabled`: `true` when `drive_sync.enabled` is set in config.
  - `connected`: `true` if a refresh token is present in the token store.
  - `last_vault_sync`: RFC3339 timestamp of the last successful upload or download, or `null` if none yet.
  - `last_pebble_backup`: RFC3339 timestamp of the last successful Pebble backup (from US-19), or `null`.
  - `last_error`: last sync error string, or `null` if the last operation succeeded.
- When `connected: false`, the UI displays a prompt explaining that the user needs to sign out and back in to grant Drive access.
- The UI shows `last_vault_sync` as a human-readable relative timestamp (e.g. "2 minutes ago") with an absolute tooltip.
- When `enabled: false`, the status endpoint still responds (with `enabled: false` and all other fields `null`) — it does not 404.

## Architecture Notes

- **Handler location**: `internal/drivesync/handler.go` — consistent with all other feature packages owning their own handler (`dream`, `chat`, `attachment`). Using `internal/sync/` would shadow the stdlib `sync` package.

- **`SyncManager.Status()`** — the handler must not read Pebble state keys directly. Instead, `SyncManager` exposes a `Status() DriveStatus` method that reads from its own `state` (`State`) and `tokenStore` (`store.DriveTokenStore`). Both are already held by `SyncManager`; no new dependencies required.

- **`StatusProvider` interface** — defined in `internal/drivesync/`, implemented by `SyncManager`. The handler accepts this interface, making it fully testable with a fake. When Drive sync is disabled, `main.go` passes `nil`; the handler returns `{enabled: false, ...nulls}`.

- **Nullable fields** — `DriveStatus` uses `*string` for `LastVaultSync`, `LastPebbleBackup`, and `LastError` so they JSON-encode as `null` when absent. `State.Get*()` returns `""` on miss; `Status()` converts empty string → nil pointer.

- **`connected` check** — `SyncManager.Status()` calls `sm.tokenStore.GetDriveToken()`; a non-empty return means connected. No new Pebble key needed.

- **Server wiring** — add a `drivesync.StatusProvider` field to `Server` alongside the existing `driveTokenStore`. Pass `sm` from `main.go` when Drive sync is enabled, `nil` when disabled. Register `GET /api/drive/status` (auth-guarded) in `routes()`. This follows the same injection pattern as `dream.ConsolidateFn`.

- **`last_pebble_backup`** — returns `null` until US-19 is implemented. `State` has no such key yet; `Status()` returns nil for that field.

## Implementation Checklist

### Group 1 — API endpoint
_Observable: `curl -b "autowiki_session=<tok>" http://localhost:8080/api/drive/status` returns correct JSON._

- [ ] Add `DriveStatus` struct to `internal/drivesync/` with fields `Enabled bool`, `Connected bool`, `LastVaultSync *string`, `LastPebbleBackup *string`, `LastError *string`.
- [ ] Add `StatusProvider` interface to `internal/drivesync/`: single method `Status() DriveStatus`.
- [ ] Add `Status() DriveStatus` method to `SyncManager`: reads `state.GetLastVaultSync()`, `state.GetLastError()`, and `tokenStore.GetDriveToken()` (non-empty → `Connected: true`); converts empty strings to nil pointers; `LastPebbleBackup` always nil until US-19.
- [ ] Add `internal/drivesync/handler.go`: `NewStatusHandler(p StatusProvider) http.Handler`. When `p == nil`, responds with `{"enabled":false}` and all pointer fields null. Otherwise JSON-encodes `p.Status()`.
- [ ] Add `statusProvider drivesync.StatusProvider` field to `Server` in `internal/server/server.go`; update `New()` signature.
- [ ] Register `GET /api/drive/status` (auth-guarded) in `routes()`.
- [ ] In `main.go`, pass `sm` as `StatusProvider` when Drive sync is enabled, `nil` otherwise.
- [ ] Tests:
  - `Status()` returns `Connected: true` when token store has a token.
  - `Status()` returns `Connected: false` when token store returns empty string.
  - `Status()` converts non-empty `LastVaultSync` string to a non-nil pointer.
  - `Status()` converts empty `LastVaultSync` string to nil.
  - `Status()` converts non-empty `LastError` string to a non-nil pointer; empty to nil.
  - Handler returns `{"enabled":false}` with null fields when provider is nil.
  - Handler returns correct JSON when provider returns a populated `DriveStatus`.

### Group 2 — Frontend status indicator
_Observable: status icon visible in the UI; updates every 60 s._

- [ ] On mount in the home route, fetch `GET /api/drive/status`. Poll every 60 seconds while the page is open (use `setInterval`, clear on unmount).
- [ ] Render states:
  - `enabled: false`: no indicator shown.
  - Enabled, `connected: false`: amber warning — "Sign out and back in to enable Drive sync."
  - Enabled, connected, `last_error` non-null: red indicator with the error message.
  - Enabled, connected, no error: green indicator — "Synced [relative time]" with absolute tooltip.
- [ ] Use the existing `formatRelative` helper for `last_vault_sync`.
