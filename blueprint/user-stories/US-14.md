# US-14 — Search past conversations

**As a user**, I can ask autowiki something like "didn't we discuss X last week?" and have it search through past chat sessions to find the relevant conversation, so that knowledge shared in earlier sessions is never lost.

## Acceptance Criteria

- When the user signals recall (e.g. "didn't we talk about…", "what did I say about…", "remember when…") or when the model judges that the answer may lie in a past session, it searches chat history before responding.
- Search covers both user and assistant messages across past sessions.
- Search is paginated: each call scans 3 sessions at a time, newest first. The model may call again with a higher offset to look further back.
- Search stops after 50 sessions total (offset cap enforced in the tool definition and system prompt).
- Matching results include the session date and a short snippet of the matching message so the model can judge relevance without reading full transcripts.
- The model uses its judgement to stop searching once it finds a relevant result or concludes the topic was never discussed.

## Implementation Checklist

### Group 1 — Store: `SearchMessages`

- [ ] Add `MessageSearchResult` struct to `store` package: `SessionDate string`, `Role string`, `Snippet string`.
- [ ] Add `SearchMessages(query string, sessionOffset, sessionLimit int) ([]MessageSearchResult, error)` to the `ChatStore` interface.
  - Loads sessions newest-first starting at `sessionOffset`, up to `sessionLimit` sessions.
  - For each session, loads all messages and does a case-insensitive substring match on `Content`.
  - Skips `tool_result` role messages (noisy internal plumbing).
  - For matching messages, trims `Content` to a 300-character snippet.
  - Returns all matches across the scanned sessions.
- [ ] Implement on `MemChatStore`.
- [ ] Implement on `PebbleChatStore`.
- [ ] Tests (shared suite in `chat_test.go`):
  - Returns matches from user messages.
  - Returns matches from assistant messages.
  - Skips `tool_result` messages.
  - Snippets are trimmed to 300 characters.
  - `sessionOffset` skips the newest N sessions.
  - Returns empty slice when no sessions exist.
  - Returns empty slice when query matches nothing.

### Group 2 — LLM: tool definition + system prompt

- [ ] Add `search_chat_history` tool definition with inputs `query` (string) and `offset` (int, default 0).
  - Description makes clear: scans 3 sessions per call, call again with `offset+3` to go deeper, max offset is 50.
- [ ] Add instruction to system prompt: use `search_chat_history` when the user signals recall or when the answer may be in a past session; stop searching after a reasonable number of calls without a hit.
- [ ] Tests:
  - `search_chat_history` tool is present in every request.
  - System prompt mentions `search_chat_history` and when to use it.

  - Emit a `status` SSE event ("Searching chat history…") before the call.
