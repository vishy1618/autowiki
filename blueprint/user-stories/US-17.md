# US-17 — Sync Drive changes back to vault

**As a user**, I want changes made to vault files in Google Drive to be automatically pulled back to my local vault so that edits made on other devices are reflected locally.

## Background

Depends on US-16. This story adds the Drive→local direction: a polling goroutine detects remote changes and downloads them. It also completes bidirectional startup reconciliation (US-16 only uploaded local-only files) and introduces conflict resolution for files modified on both sides.

## Acceptance Criteria

- A polling goroutine runs every `drive_sync.poll_interval_secs` seconds (default 60). On each tick it calls `ListChanges` with the stored page token, processes all changes, then persists the new page token.
- For each changed Drive file within the vault folder:
  - New or updated → download to the local path (applying conflict resolution if the file already exists locally).
  - Trashed or permanently deleted → delete the local file and remove its State entry.
- On startup, `Reconcile` downloads Drive-only files (present in Drive, absent from State). Combined with US-16's upload walk this completes full bidirectional reconciliation.
- **Conflict resolution** follows `drive_sync.conflict_strategy`:
  - `last_write_wins` (default): whichever side has the later `modifiedTime` wins; the other is silently overwritten.
  - `keep_both`: same as `last_write_wins` when timestamps differ by more than 5 seconds. When both sides were modified within a 5-second window, the older version is renamed to `<stem>.conflict.<YYYYMMDDHHMMSS><ext>` before the newer version is written.
- Sync errors are logged but do not crash the server or affect chat.

## Architecture Notes

- **`syncJob` / `syncCh`** replace `uploadJob` / `uploadCh` in `manager.go`. The channel now serialises uploads, downloads, and trashes. Rename in Group 1.
- **`Reconcile` / `reconcile`** replace the public `ReconcileUpload` and private `reconcileUpload`. Rename in Group 2.
- **`Upload` return value** currently returns `(driveID string, error)`. Change to `(driveID, md5, modifiedTime string, error)` in Group 1 so `processJob` can populate the `MD5` and `DriveModTime` fields that already exist in `FileEntry` but were left empty by US-16.
- **`DriveChange` struct** — `{FileID string, Removed bool, Name string, ParentID string, ModifiedTime string, MD5 string}`. `Name` and `ParentID` come from Drive file metadata included in change events (populated for trashed files; absent for permanent deletes). `ListChanges` handles pagination internally and returns all changes for one poll cycle plus the `newStartPageToken` to use on the next call.
- **RelPath resolution** is the manager's responsibility, not the Drive client's. Two reverse-lookup helpers on `State` support it:
  - `GetFolderByDriveID(driveID string) (relPath string, error)` — scans the `drive_sync:folders:` prefix.
  - `GetFileByDriveID(driveID string) (relPath string, error)` — scans the `drive_sync:files:` prefix; used when a permanent-delete change arrives without `Name`/`ParentID`.
  - Private manager method `resolveRelPath(change DriveChange) (relPath string, ok bool)`: if `change.ParentID == sm.vaultFolderID` then `relPath = change.Name`; otherwise resolve via `GetFolderByDriveID(change.ParentID)`. Returns `false` if the parent is not in State (change is outside the vault — skip it).
- **`ConflictStrategy` type** — defined in `internal/config/config.go` as `type ConflictStrategy string` with exported constants `ConflictLastWriteWins` and `ConflictKeepBoth`. `DriveSyncConfig.ConflictStrategy` changes from `string` to `ConflictStrategy`.
- **`conflict.go`** lives in `internal/drivesync/` (not `internal/sync/` — that name shadows the stdlib). `Resolve` is a **pure function** returning `ConflictDecision{Winner string, ConflictPath string}`. It performs no filesystem I/O; the caller is responsible for any rename and the actual download. This keeps the decision logic fully unit-testable without touching disk.
- **`startPoller`** is an extracted method on `SyncManager`, called from `Start()` after `reconcile`. Parallels the existing `startWorkerOnce` pattern and keeps `Start()` readable.

### Group 3 — Conflict resolution
_Observable: edit the same file both locally and in Drive within a short window, then trigger a poll — the correct version wins and (with `keep_both`) a `.conflict.` file is created alongside it._

- [x] Add `type ConflictStrategy string` to `internal/config/config.go` with constants `ConflictLastWriteWins ConflictStrategy = "last_write_wins"` and `ConflictKeepBoth ConflictStrategy = "keep_both"`. Change `DriveSyncConfig.ConflictStrategy` from `string` to `ConflictStrategy`. Update `validate()` default accordingly.
- [x] Implement `internal/drivesync/conflict.go`:
  - `type ConflictDecision struct { Winner string; ConflictPath string }` — `Winner` is `"local"` or `"drive"`; `ConflictPath` is non-empty only when a conflict file must be created by the caller.
  - `func Resolve(localModTime, driveModTime time.Time, strategy ConflictStrategy) ConflictDecision` — pure, no filesystem I/O.
    - `last_write_wins`: whichever timestamp is later; `ConflictPath` always empty.
    - `keep_both`, gap > 5 s: same as `last_write_wins`; `ConflictPath` empty.
    - `keep_both`, gap ≤ 5 s: `Winner = "drive"`; `ConflictPath` is the older file's name with `conflict.<YYYYMMDDHHMMSS>` inserted before the extension (caller resolves full path and performs the rename).
- [x] Wire conflict resolution into `processJob` for download jobs: if local file exists, `stat` it for `modifiedTime`, call `Resolve`; skip download if `Winner == "local"`; rename local file to `ConflictPath` before writing if `ConflictPath != ""`.
- [x] Wire the same conflict logic into the `reconcile` download path.
- [x] Tests:
  - `last_write_wins`: Drive newer → `"drive"`; local newer → `"local"`; within 5 s → still picks the later timestamp.
  - `keep_both`, > 5 s apart: picks later side, `ConflictPath` empty.
  - `keep_both`, ≤ 5 s apart: `Winner = "drive"`, `ConflictPath` has correct `conflict.<timestamp>` format.
  - `processJob` download: skips download when local wins; renames to `ConflictPath` and downloads when conflict is triggered.
