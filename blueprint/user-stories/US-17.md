# US-17 — Sync Drive changes back to vault

**As a user**, I want changes made to vault files in Google Drive to be automatically pulled back to my local vault so that edits made on other devices are reflected locally.

## Background

Depends on US-16 (Drive client, sync state, and watcher infrastructure). This story adds the Drive→local direction: a polling goroutine detects remote changes and downloads them. It also completes the initial reconciliation (US-16 only uploaded local-only files; this story adds download of Drive-only files) and introduces conflict resolution for files modified on both sides.

## Acceptance Criteria

- A polling goroutine runs every `drive_sync.poll_interval_secs` seconds (default 60), calling `changes.list` with the stored page token. The updated page token is persisted in Pebble after each poll.
- For each changed Drive file within the vault folder:
  - If the file was updated in Drive and exists locally, apply conflict resolution (see below) then download if Drive wins.
  - If the file was updated in Drive and does not exist locally, download it.
  - If the file was trashed in Drive and exists locally, delete the local file.
- On first start (as part of `Reconcile`), Drive-only files (present in Drive but absent locally) are downloaded. This completes the full bidirectional reconciliation started in US-16.
- **Conflict resolution** follows `drive_sync.conflict_strategy`:
  - `last_write_wins` (default): the side with the later `modifiedTime` wins; the other is silently overwritten regardless of how close the timestamps are.
  - `keep_both`: behaves identically to `last_write_wins` when the two `modifiedTime` values differ by more than 5 seconds. When both sides were modified within a 5-second window, the older version is renamed to `<name>.conflict.<YYYYMMDDHHMMSS>.md` before the newer version is written.
- Local deletions continue to trash the Drive file (already implemented in US-16). Drive deletions delete the local file (added here).
- Sync errors are logged but do not crash the server or affect chat.

## Implementation Checklist

### Group 1 — Drive API: download and list changes

- [ ] Add `Download(driveFileID, localPath string) error` to `DriveClient` — downloads a Drive file to a local path, creating parent directories as needed.
- [ ] Add `ListChanges(pageToken string) (changes []DriveChange, nextPageToken, newStartPageToken string, error)` to `DriveClient`. `DriveChange`: `{FileID, Removed bool, ModifiedTime, RelPath string}`. The manager resolves `RelPath` from the file's name and parent chain.
- [ ] Tests: Download and ListChanges behave correctly against a fake HTTP transport.

### Group 2 — Conflict resolution (`internal/sync/conflict.go`)

- [ ] Implement `Resolve(localPath string, localModTime, driveModTime time.Time, strategy string) (winner string, error)` returning `"local"` or `"drive"`.
  - `last_write_wins`: return whichever `modTime` is later.
  - `keep_both`: if `|localModTime - driveModTime| > 5s`, return the later side. If ≤ 5 s, save the older version as `<name>.conflict.<YYYYMMDDHHMMSS>.md` and return `"drive"` (Drive version written to the canonical path).
- [ ] Tests:
  - `last_write_wins`: Drive newer → `"drive"`; local newer → `"local"`; within 5 s → still just picks later.
  - `keep_both`, > 5 s apart: picks later side, no conflict file.
  - `keep_both`, ≤ 5 s apart: conflict file created with correct name; returns `"drive"`.

### Group 3 — Sync manager: download path and full reconcile

- [ ] Add `Download(driveFile DriveFile) error` to `SyncManager`: runs conflict resolution against the local file (if present), then downloads if Drive wins. Updates `State` on success.
- [ ] Extend `Reconcile` (previously `ReconcileUpload`) to also download Drive-only files: list Drive folder contents, compare against `State`, download any file with no local state entry.
- [ ] Add polling goroutine to `SyncManager.Start`: every `poll_interval_secs`, call `ListChanges`, process each `DriveChange`, update page token in `State` via `SetPageToken`.
- [ ] Handle Drive deletions in the polling path: if `DriveChange.Removed` and local file exists, delete it and remove its state entry.
- [ ] Update `SetLastVaultSync` / `SetLastError` from the polling goroutine.
- [ ] Tests:
  - Polling goroutine downloads a changed Drive file and updates page token.
  - Polling goroutine deletes a local file when Drive file is trashed.
  - `Reconcile` downloads Drive-only files in addition to uploading local-only files.
  - Full conflict resolution exercised in download path for both strategies (delegate to conflict package tests).
