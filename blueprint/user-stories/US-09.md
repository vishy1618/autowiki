# US-09 — Scroll back through chat history

**As a user**, I can scroll back through my entire chat history in a single continuous view so that I can recall any past conversation or piece of knowledge I have shared, regardless of when it occurred.

## Acceptance Criteria

- The chat interface presents all messages as one unbroken timeline with no visible session concept beyond a subtle divider between sessions.
- On load, the last 3 sessions are fetched and rendered, newest messages at the bottom.
- Scrolling to the top fetches the next older session and prepends it, continuing until all history is loaded.
- Every message shows a relative timestamp ("2 hours ago") with the absolute datetime as a hover tooltip.
- A subtle visual divider separates messages from different sessions.

## Implementation Checklist

### Group 1 — Store: ListSessions

- [x] Add `ListSessions(limit, offset int) ([]ChatSession, error)` to the `ChatStore` interface. Returns sessions newest-first; `limit` caps the count, `offset` skips the first N sessions (for pagination).
- [x] Implement in `MemChatStore`.
- [x] Implement in `PebbleChatStore`.
- [x] Tests for both implementations:
  - Returns empty slice when no sessions exist.
  - Returns sessions newest-first.
  - Respects `limit`.
  - Respects `offset` (returns next page).

### Group 2 — API: chat-sessions endpoints

- [x] Register `GET /api/chat-sessions` on the server mux. Query params: `limit` (default 3), `offset` (default 0). Returns `{ "sessions": [{ "id", "created_at", "last_active_at" }] }`.
- [x] Register `GET /api/chat-sessions/{id}` on the server mux. Returns `{ "messages": [{ "id", "role", "content", "created_at" }] }`. Returns 404 if session not found.
- [x] Tests:
  - `GET /api/chat-sessions` returns sessions newest-first with correct pagination.
  - `GET /api/chat-sessions/{id}` returns messages in insertion order.
  - `GET /api/chat-sessions/{id}` returns 404 for unknown session.
  - Both endpoints require auth (return 401 when unauthenticated).

### Group 3 — Frontend: timestamps

- [x] Add a `createdAt: string` (ISO string) field to the frontend `Message` interface.
- [x] Write a `formatRelative(iso: string): string` helper that returns strings like "just now", "5 minutes ago", "3 hours ago", "yesterday", "13 Apr".
- [x] Render each message's relative timestamp below the bubble content, with the full absolute datetime as the `title` attribute (tooltip).
- [x] Tests:
  - `formatRelative` returns expected strings for each time range.

### Group 4 — Frontend: multi-session load and infinite scroll

- [x] On mount, fetch the last 3 sessions (`GET /api/chat-sessions?limit=3`) and for each fetch its messages (`GET /api/chat-sessions/{id}`). Flatten into a single message list with session-divider markers, oldest first.
- [x] Render a subtle horizontal divider element between sessions (no label needed).
- [x] Place an `IntersectionObserver` sentinel `<div>` at the top of the message list. When it becomes visible and there are more sessions to load, fetch the next session (increment offset by 3), prepend its messages and divider to the list.
- [x] Once all sessions have been loaded, disconnect the observer and remove the sentinel.
- [x] Show a subtle loading indicator while a session fetch is in progress.
- [x] Tests:
  - Initial render shows messages from the last 3 sessions.
  - Session dividers are rendered between sessions.
  - Timestamps are rendered on each message.
  - Sentinel triggers fetch of older sessions and prepends them.
  - No fetch occurs when fewer than limit sessions were returned (no more history).
