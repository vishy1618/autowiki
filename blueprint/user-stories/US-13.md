# US-13 — Sliding session expiry

**As a user**, my login session stays alive as long as I am actively using the app, so that I am not unexpectedly logged out mid-session.

## Acceptance Criteria

- The session expiry slides: each authenticated request resets the expiry to `now + 30 minutes`.
- The browser cookie `MaxAge` is updated on every response so the browser-side expiry stays in sync.
- An absolute maximum lifetime of 30 days is enforced — a session cannot slide indefinitely regardless of activity.
- A session that has genuinely been idle for 30 minutes still expires as before.

## Design Notes

- **No token rotation.** The same token is extended in place. Token rotation defends against stolen tokens being reused after the real user acts — a threat already largely mitigated by `HttpOnly`, `Secure`, and `SameSite=Lax` on the cookie. The concurrency hazard of rotation (two simultaneous requests racing on a single-user tool) is not worth the added complexity.
- The refresh is applied in the auth middleware so it covers every authenticated route uniformly.
- To avoid a Pebble write on every single API call, refresh only when the session has less than half its remaining time left (i.e. when `ExpiresAt - now < 15 minutes`). This bounds DB writes to at most once per 15-minute window.
- The absolute max is stored as `CreatedAt + 30 days` and checked alongside the inactivity window.
