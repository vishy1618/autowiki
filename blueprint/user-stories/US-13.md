# US-13 — Sliding session expiry

**As a user**, my login session stays alive as long as I am actively using the app, so that I am not unexpectedly logged out mid-session.

## Status: Complete

## Acceptance Criteria

- The session expiry slides: each authenticated request that triggers a refresh resets the expiry to `now + 30 minutes`.
- A new token is issued on each refresh (token rotation) and the old token is invalidated — a stolen token becomes useless the moment the legitimate user makes the next request.
- The browser cookie is updated with the new token and `MaxAge` on every rotation.
- An absolute maximum lifetime of 30 days is enforced — a session cannot slide indefinitely. This is stored separately and carried forward unchanged across rotations.
- A session genuinely idle for 30 minutes still expires as before.
- If two requests arrive simultaneously during a rotation, a 30-second grace window accepts the just-superseded token, preventing spurious logouts from browser parallelism.

## Design Notes

### Why token rotation
The app is internet-facing. Token rotation ensures a stolen session cookie is invalidated as soon as the legitimate user acts. `HttpOnly` + `Secure` + `SameSite=Lax` reduce theft opportunities but cannot eliminate them entirely on the public internet.

### Refresh threshold
Rotate only when `expires_at - now < 15 minutes` (the second half of the 30-minute window). This bounds Pebble writes to at most one per 15-minute window rather than on every API call, while still guaranteeing the session stays alive during active use.

### Absolute maximum
`Session` gains an `AbsoluteExpiresAt` field set once at login (`created_at + 30 days`) and carried forward unchanged across all rotations. `GetSession` rejects sessions where `now > absolute_expires_at` regardless of the rolling expiry.

### Rotation data flow
1. Middleware detects session is in the second half of its window.
2. Generate new token; write new `Session{token: new, expires_at: now+30m, absolute_expires_at: (unchanged)}`.
3. Overwrite old token record with a tombstone expiring in 30 seconds (grace window for in-flight requests).
4. Set `Set-Cookie` with new token and updated `MaxAge`.

### Concurrency
The 30-second grace window on the old token means two simultaneous browser requests (e.g. prefetch + navigation) both succeed. After 30 seconds the old token is gone.
