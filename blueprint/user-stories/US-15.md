# US-15 — Search the web and fetch URLs

**As a user**, I can share a URL or ask autowiki to look something up online, and have it fetch and read the content so that knowledge from the web can flow into our conversation and into my vault.

## Acceptance Criteria

- When the user shares a URL, the model fetches and reads it without being asked explicitly.
- When the user asks to look something up (e.g. "find me the latest on X", "what does the docs say about Y"), the model searches the web and fetches the most relevant result.
- The model uses its judgment to decide whether fetched content is worth saving to the vault — it should save substantive articles, documentation, or research, but not transient or low-value pages.
- A status line is shown while searching or fetching so the user knows the model is working.
- JavaScript-rendered pages are a known limitation and do not need to be handled.

## Design Notes

Both tools are Anthropic-native (no external API keys required):

- **`web_search_20250305`** — general queries; costs $0.01 per search.
- **`web_fetch_20250910`** — fetches a specific URL (including PDFs); no extra charge beyond token costs.

The natural flow for a lookup: `web_search` → model picks the best URL → `web_fetch` → model answers and optionally saves to vault.
The natural flow for a shared URL: skip `web_search`, go straight to `web_fetch`.

Both tools are handled server-side by Anthropic — there is no Go dispatch logic needed. The chat handler already stores all tool results that arrive in the SSE stream; these tools behave identically to vault tools from the handler's perspective.

The `status` SSE events for these tools come from the existing agentic loop — if the model emits a text block before calling a tool the UI already shows it. The only new wiring needed is ensuring the system prompt guides when to use each tool.

  - System prompt mentions `web_search` and when to use it.

### Group 3 — Chat handler: status events

- [ ] Add `"web_search"` and `"web_fetch"` cases to the tool dispatch switch.
  - Both are no-ops for Go logic (Anthropic handles execution) but each should emit a `status` SSE event so the user sees activity.
  - `web_search`: emit `{"message":"Searching the web…"}`.
  - `web_fetch`: parse the URL from the tool JSON and emit `{"message":"Fetching <url>…"}`.
  - Store the tool result (already arrives in the SSE stream from Anthropic).
- [ ] Tests:
  - Handler emits status event on `web_search` tool call.
  - Handler emits status event on `web_fetch` tool call with the URL in the message.
