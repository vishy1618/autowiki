# US-05 — Share an image

**As a user**, I can attach an image (or other file) to a chat message so that its content is interpreted, described, and indexed in my vault.

## Acceptance Criteria

- Files are uploaded immediately on selection/drop, in parallel with the user typing their message.
- The file is saved to `_attachments/` inside the vault with a collision-safe name: `{original-stem}-{yyyyMMdd-shortid}.{ext}`.
- A sidecar `{filename}.meta.json` is written alongside the file containing `{ id, original_name, media_type, description, uploaded_at }`.
- For images: a concise LLM-generated description is stored in the sidecar at upload time.
- For non-image files: `description` is an empty string in the sidecar (future stories will handle extraction).
- When the user sends a message referencing uploaded attachments, the chat handler injects the description(s) into conversation context; the image is not re-sent to the LLM.
- The `save_to_vault` tool embeds attachments using Obsidian syntax: `![[filename.ext]]`.
- The frontend shows a thumbnail preview for images and a file-type card (no preview) for other files.
- Attachments can be added via a file picker button or by dragging and dropping onto the chat area.

## Design Notes

- `_attachments/` is permanent storage in the vault, not a staging area. Files are never moved after upload.
- Filename generation: `{original-stem}-{yyyyMMdd}-{6-char-random-hex}.{ext}`, e.g. `screenshot-20260413-a3f9c1.png`. Original name preserved in sidecar.
- The pre-upload endpoint is auth-protected. It returns `{ id, path, description }` immediately so the frontend can show a preview and attach the reference to the outgoing message.
- Attachment references are passed to `POST /api/chat` as `attachment_ids[]`; the handler resolves them to descriptions via the sidecar.

## Implementation Checklist

### Vault Manager — attachment support (`internal/vault`)
- [x] `SaveAttachment(originalName string, data []byte) (path string, err error)` — generates collision-safe filename, writes file to `_attachments/`, returns vault-relative path
- [x] `WriteAttachmentMeta(path string, meta AttachmentMeta) error` — writes `{path}.meta.json` sidecar
- [x] `ReadAttachmentMeta(path string) (AttachmentMeta, error)` — reads sidecar by vault-relative path
- [x] `AttachmentMeta` struct: `ID`, `OriginalName`, `MediaType`, `Description`, `UploadedAt`
- [x] Unit tests for filename collision-safety, sidecar round-trip

### LLM Client — image description (`internal/llm`)
- [x] `DescribeImage(ctx, data []byte, mediaType string) (string, error)` — sends image as base64 vision message; prompt asks for a concise description suitable for knowledge indexing
- [x] Unit tests with stubbed HTTP transport

### Attachment Handler (`internal/attachment`)
- [x] Define `Handler` struct wiring `vault.Manager` and `llm.Client` (via a `Describer` interface)
- [x] `POST /api/attachments` — accepts multipart `file` field; saves file, generates description for images (empty string for others), writes sidecar, returns `{ id, path, description }`
- [x] Handler tests: image upload returns description, non-image upload returns empty description, missing file returns 400

### Chat Handler — attachment context (`internal/chat`)
- [x] `POST /api/chat` accepts optional `attachment_ids[]` form field
- [x] Handler reads sidecar for each ID and prepends attachment context to the conversation before calling the LLM: `[Attached: {original_name} — {description}]`
- [x] Handler tests: message with attachment injects context, unknown attachment ID is silently skipped

### Server wiring (`internal/server`)
- [x] Register `POST /api/attachments` (auth-protected) using the attachment handler
- [x] Pass `vault.Manager` to the attachment handler

### Frontend — attachment UI (`web/app/routes/home.tsx`)

- [x] Drag-and-drop zone over the chat area; drop overlay shown on dragover
- [x] On file selected/dropped: immediately `POST /api/attachments`, show upload chip with spinner
- [x] On upload complete: show image thumbnail (for images) or file-type card (for others); both are dismissible
- [x] On send: include `attachment_ids[]` in the form body alongside `message`
- [x] In the sent user bubble: render thumbnail/file card for each attachment above the message text
- [x] Tests: file picker triggers upload, attachment chip shown after upload, attachment_ids sent with message
